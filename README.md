# Skill Intelligence Engine

> **A corpus-agnostic intelligence layer for retrieving, ranking, explaining, evaluating and
> composing skills — not a repository of skills itself.**
>
> Point it at any directory of `SKILL.md` files (YAML frontmatter + markdown sections). It
> indexes them (BM25 + dense embeddings), routes a free-text task to the right skill with
> per-retriever evidence and a routing confidence (route / clarify / abstain), splits
> multi-part requests into a dependency-ordered skill plan, builds learning paths from typed
> skill relationships, and measures all of it against labeled query sets.

[![python](https://img.shields.io/badge/python-3.11%2B-blue)]()

| | what it is | what it provides |
|---|---|---|
| a skill corpus, e.g. [`ml-ai-skills`](https://github.com/NiravRVaghasiya/ml-ai-skills) | content: one `SKILL.md` per skill | the knowledge, and `requires` / `related` / … declarations |
| **this repo** | an engine over *any* such corpus | retrieval, ranking, evidence, confidence, composition, learning paths, evaluation, API |

The repo vendors one corpus, `ml-ai-skills@8328c60` (38 skills, `data/skills/`, described by
`data/skills/corpus.toml`), so the benchmarks are reproducible. Nothing in `sie/` depends on
it: [use your own corpus](#use-your-own-corpus) by pointing `--skills` / `SIE_SKILLS_DIR` at it.

<!-- BEGIN:headline -->
**Top-1 routing accuracy goes from 43.2% to 95.5%** on 88 labeled queries (keyword router -> SIE: hybrid RRF (--no-rerank)), and from 34.8% to 82.6% on the 23 queries taken from the source repo's own eval cases. _Generated by `python -m eval.run_eval`._
<!-- END:headline -->

These numbers are on one 38-skill corpus with LLM-written and corpus-author-written queries
(see [who wrote the queries](#caveats-read-before-quoting-any-number)). They are not a claim
about other corpora, real user traffic, or scale.

On the 23 queries taken from the source repo's own `evals/` cases: keyword top-1 **0.348** / MRR 0.536 vs SIE top-1 **0.826** / MRR 0.895. CIs, paired deltas, tie sensitivity, ablations and every miss: [`benchmarks/RESULTS.md`](benchmarks/RESULTS.md). _Generated by `python -m eval.run_eval`._

**What the ablations say (computed):**

- **Main set, where the lexical gain comes from:** BM25 over the Card chunks alone (about the fields the keyword router reads) takes top-1 from 0.432 to 0.727 (better term weighting on the same text). Indexing the body sections too raises it to 0.920.
- **Source-authored set, where the lexical gain comes from:** BM25 over the Card chunks alone (about the fields the keyword router reads) takes top-1 from 0.348 to 0.696 (better term weighting on the same text). Indexing the body sections too lowers it to 0.652.
- **Main set:** the stronger single retriever is **BM25 only** (MRR 0.949 vs 0.927). SIE: hybrid RRF (--no-rerank) is +0.023 MRR against it and +0.399 against the keyword router.
- **Source-authored set:** the stronger single retriever is **dense only** (MRR 0.906 vs 0.749). SIE: hybrid RRF (--no-rerank) is -0.011 MRR against it and +0.359 against the keyword router.
- The keyword router is strongest on `-` queries (top-1 0.92; `-` marks the scaffold's original 12) and weakest on `symptom` queries (top-1 0.00).

**Beyond top-1 (computed):**

- **Out of scope (30 queries no skill fits):** SIE: hybrid RRF (--no-rerank) abstains on 87%, asks on 13% and routes 0% anyway; the keyword router has no way to abstain, and its `route()` as shipped returned skills for every one. In scope it abstains on 0.9% of queries.
- **Multi-intent (25 requests, 63 gold intents):** `compose()` covers on average 64% of each request's gold intents (60% of all 63 pooled), with 32% exact plans; routing the whole request and taking the top-1 covers on average 48% (38% pooled; 20% exact). The same ranking's top-n with the true intent count (an oracle no caller has) covers on average 77% (75% pooled; 44% exact). `compose()` was revised after its first measurement on this set, so its numbers are not held-out (see RESULTS.md).
- Confidence levels are heuristic and uncalibrated; how often each level is right is measured per set in RESULTS.md.

### Caveats (read before quoting any number)

- **Reranker:** the cross-encoder row says *pending* because `huggingface.co` was unreachable
  where this was built. The headline system is hybrid RRF without a reranker. No reranker
  quality or latency number exists in this repo.
- **Who wrote the queries:** every set is labeled with its origin in `eval/datasets.toml`.
  76 of the 88 main queries, all 30 out-of-scope and all 25 multi-intent queries were written
  by LLM agents that saw only the skill catalog, audited by separate agents, and frozen
  (sha256 in RESULTS.md) before any system ran on them. The 23 source-authored queries were
  written by the corpus author. None is independently collected user traffic.
- **Confidence is heuristic.** Levels are rules over retriever agreement, similarity and
  lexical coverage with thresholds fixed a priori, not probabilities. RESULTS.md measures how
  often each level is right. One rule (BM25-only mode) was changed after the first
  measurement; RESULTS.md says which and why.
- **Multi-intent composition is below a simple oracle.** `compose()` covers more intents than
  routing the whole request once, but fewer than taking the top-n skills when n (the true
  number of intents) is known. It is opt-in and experimental.
- **Scale:** retrieval *quality* is measured on 297 chunks only. *Latency* is measured on one
  laptop-class CPU ([PERFORMANCE.md](benchmarks/PERFORMANCE.md)): `route()` p50 ≈ 0.13 s at the
  default pool, dominated by query embedding; on a synthetic 16× replication (4,752 chunks,
  latency only) p50 ≈ 0.16 s, with pure-Python BM25 the stage that grows (≈3 → 69 ms). Nothing
  here shows retrieval quality on a large corpus.
- **Ties:** every system breaks exact score ties alphabetically; RESULTS.md reports how much
  of each top-1 that decides.

## What a routing answer looks like

```text
$ python -m sie.router "impute missing values and encode categoricals" --no-rerank -k 3 --explain
[router] mode=hybrid ranking=rrf
 1. data-preprocessing           score=0.033  [Card]
      dense  #1   cosine=0.477  [Card]
      bm25   #1   bm25=22.700  [Card]  terms: impute, missing, values, encode
 2. feature-engineering          score=0.032  [Workflow]
      dense  #2   cosine=0.438  [Workflow]
      bm25   #2   bm25=9.642  [Workflow]  terms: values, and, encode, categoricals
 3. ml-problem-framing           score=0.030  [Workflow]
      dense  #9   cosine=0.226  [Workflow]
      bm25   #5   bm25=5.607  [Workflow]  terms: missing, values, and
[router] confidence: high (route): dense and bm25 rank data-preprocessing first

$ python -m sie.router "set up retrieval over my company docs and check answers are grounded" --no-rerank -k 3
 1. rag-evaluation               score=0.033  [Workflow]
 2. rag-pipeline                 score=0.032  [Overview]
 3. llm-evaluation               score=0.032  [Card]
[router] confidence: medium (clarify): bm25 ranks llm-evaluation first

$ python -m sie.router "what's a good pizza place in Naples" --no-rerank
[router] confidence: none (abstain): no sufficiently good match: best dense similarity 0.12 < 0.30; only 26% of the query's term weight matches the best candidate (< 40%)
```

`POST /route` returns the same thing as JSON: ranked `results` (each with `skill_id`, `rank`,
`score` + `score_type`, `retrieval_methods`, `evidence`, `provenance`, direct `prerequisites`),
`confidence` (`level`, `action`, `ambiguous`, `reasons`, `competitors`, raw `signals`,
`calibrated: false`), `alternatives`, candidate counts, per-stage `timings_ms` and the corpus
identity. An agent can act on `action`: `route`, ask the user to choose among `alternatives`
(`clarify`), or say nothing fits (`abstain`). Chunk ids and server paths are never returned.

**Confidence rules** ([`sie/confidence.py`](sie/confidence.py)): `none` when the dense
similarity *and* lexical coverage of the best candidate are both weak; `low` when the top
result's own evidence is weak or a retriever didn't find it; `medium` (ambiguous) when another
skill is some retriever's #1 or the top two tie; `high` when every retriever ranks it first.

## Multi-intent requests (experimental, opt-in)

Single-skill routing stays the default. `--multi` / `"multi_intent": true` runs
`query → candidate intents → skills → declared prerequisites → ordered plan`:
it splits only at sentence boundaries and at commas/conjunctions followed by a task verb,
resolves "it"/"them" to the first request's object, routes each part, keeps parts that don't
abstain, adds only *declared* `requires` prerequisites, and orders the plan topologically (hard
prerequisites first, then the order the user asked in). Ambiguous or unmatched parts are
reported in `notes`, never silently dropped or guessed.

## Skill relationships and learning paths

| relationship (declared on skill X listing R) | meaning | used for ordering |
|---|---|---|
| `requires` | R must come before X | **hard** (the only prerequisite relation) |
| `recommended_before` | R is recommended before X | soft: orders, never adds members |
| `related` | see also R | — |
| `conflicts` | X and R conflict (symmetric) | flagged |
| `alternative_to` | X is an alternative to R (symmetric) | — |
| `specializes` | X is a narrower form of R | — |
| `supersedes` | X replaces R | noted when R is on a path |

Every edge carries `confidence` (`declared` for frontmatter) and `provenance`
(`<corpus>@<version>:<path>#<relationship>`). Overlays add edges without editing the corpus:

```text
$ python -m sie.router --path training-deep-models --overlay docs/proposed_requires.edges.json
[path] learning path to training-deep-models (2 steps, hard `requires` edges only)
  1. pytorch-patterns           [workflow/deep-learning, intermediate]
  2. training-deep-models       [workflow/deep-learning, intermediate]  <- target
  see also:  neural-net-fundamentals, hyperparameter-tuning
  conflicts: none
  why: pytorch-patterns: direct prerequisite of training-deep-models (proposed)
```

Learning paths never invent prerequisites. When the graph has too little information the
answer says so (`notes`, `complete: false`): the vendored corpus declares only 2 `requires`
edges, so most paths are the target alone, reported as "declares no prerequisites".
[docs/PROPOSED_REQUIRES.md](docs/PROPOSED_REQUIRES.md) documents 9 evidence-backed edges
proposed upstream; the overlay above applies them only on request.

## Use your own corpus

Any directory of `SKILL.md` files works. An optional `corpus.toml` at its root names it and maps
your frontmatter keys:

```toml
name = "my-skills"                 # -> Skill.source, provenance, index metadata
version = "v1.4.0"                 # -> Skill.source_version (quote it)
source = "https://example.com/my-skills"
license = "Apache-2.0"

[layout]
pattern = "**/SKILL.md"            # glob relative to the corpus root
ignore_prefixes = ["_", "."]       # template / hidden directories

[fields]                           # canonical field = your frontmatter key
requires = "prerequisites"
```

```bash
python -m sie.ingest --skills path/to/corpus               # load report: every skip has a reason
python -m sie.router --skills path/to/corpus --persist-dir data/chroma-mine --build
python -m sie.router --skills path/to/corpus --persist-dir data/chroma-mine "your task"
```

Each skill records `source`, `source_version`, `path`, `content_hash`, `updated_at` and a
`provenance` string. The dense index records the corpus fingerprint, embedder and model, and
the router refuses a stale index. Frontmatter aliases (`prerequisites`, `see_also`, …) are
accepted; unknown keys are kept as `metadata`. `scripts/setup_corpus.py --source <checkout>`
vendors a corpus and writes its manifest.

## Quickstart

```bash
git clone <this-repo> && cd skill-intelligence-engine
python -m venv .venv && . .venv/Scripts/activate      # Windows (Git Bash); `source .venv/bin/activate` elsewhere
pip install -r requirements.txt                       # everything; or pick extras (below)

python -m sie.ingest --skills data/skills --expect 38
python -m sie.router --build                          # dense index -> data/chroma/
python -m sie.router "impute missing values and encode categoricals"
python -m sie.router "build a RAG pipeline, evaluate it, then deploy it" --multi
python -m sie.router --path rag-evaluation            # no index needed

uvicorn sie.api:api                                   # OpenAPI docs at /docs
```

| install | gives you |
|---|---|
| `pip install -e .` | core: ingest, BM25 routing (`--mode sparse`), confidence, graph, learning paths, compose |
| `.[retrieval]` | dense index (chromadb + its ONNX MiniLM) |
| `.[reranker]` | cross-encoder (sentence-transformers / torch) |
| `.[api]` | FastAPI service |
| `.[evaluation]` | benchmark chart |
| `.[dev]` | pytest + API test client |

### API

| endpoint | purpose |
|---|---|
| `GET /health` | liveness + corpus identity; never loads a model |
| `GET /ready` | readiness: corpus, BM25, dense index freshness, reranker state (`degraded` if it fell back) |
| `GET /search?q=&k=&pool=&rerank_k=` | backward-compatible ranked list (+ rank, name, retrieval methods, brief confidence) |
| `POST /route` | full routing answer (evidence, confidence, alternatives, provenance); `multi_intent` adds a composed plan |
| `POST /batch-route` | up to 32 queries |
| `GET /learning-path?target=&include_recommended=` | ordered path with reasons, notes, completeness |
| `GET /skill/{slug}` | metadata, provenance, typed relations |

The service loads the corpus, BM25, the dense index and the embedding model (and the
reranker if enabled) at startup unless `SIE_EAGER_INIT=0`; a failed start keeps the process up
and `/ready` answers 503 with the reason. Routing is read-only after startup, so requests run
concurrently. Every setting is an `SIE_*` environment variable documented in
[`.env.example`](.env.example) (corpus and index paths, mode, pool, `rerank_k`, reranker,
overlays, logging). `SIE_MODE=sparse` serves with no ML dependencies at all.

### Observability

`sie.observability` emits a `route` event per call (mode, top skill, confidence, action,
candidate counts, per-stage latency) and `route_error` on failure, to the `sie.events` logger
(JSON, silent unless `SIE_LOG_LEVEL` is set) and to any hook registered with `add_hook()`.
Queries are logged as a hash and length; the raw text only with `SIE_LOG_QUERIES=1`.

### Reranker weights

The cross-encoder (`cross-encoder/ms-marco-MiniLM-L-6-v2`) loads from `$SIE_RERANKER` (a
Hugging Face id or a local directory), else `data/models/ms-marco-MiniLM-L-6-v2/`, else the
hub. If it can't load, the router says so once and falls back to RRF order (`reranked: false`,
`/ready` reports `degraded`); `SIE_STRICT_RERANK=1` makes that fatal. With weights in place,
`python -m eval.run_eval --no-build --require-reranker` fills the pending rows and
`python -m eval.perf` measures its latency per `rerank_k`. With the reranker on, results are
limited to the `rerank_k` fused skills it scored.

## Evaluation and regression protection

```bash
python -m eval.run_eval                 # every system x every set -> benchmarks/ + README blocks
python -m eval.run_eval --smoke         # no index, no models: lexical systems + recorded dense
                                        # rankings vs benchmarks/metrics.json; exit 1 on drift (CI)
python -m eval.perf                     # latency, candidate-pool sweep, synthetic scale (machine-dependent)
python -m eval.collision --source ../ml-ai-skills   # the collision case (needs that git history)
pytest -q                               # no models, no network; includes metric regression tests
SIE_INTEGRATION=1 pytest -m integration # opt-in: live index + cached models
```

Query sets live in [`eval/datasets.toml`](eval/datasets.toml), each with a `kind` (`routing`,
`out_of_scope`, `multi_intent`) and an `origin` (`scaffold`, `synthetic-llm`,
`source-authored`, `human-collected`). Add an external benchmark by adding an entry (or pass
`--datasets other.toml --out other/`); no code changes. `RESULTS.md` and `metrics.json` are
byte-reproducible and contain no timings; `tests/test_regression.py` recomputes the BM25
systems, and the hybrid system from recorded dense rankings (`tests/fixtures/`), and fails on
any metric change.

## Architecture

```
  corpus dir (SKILL.md + optional corpus.toml)
        |
  sie.corpus / sie.ingest ── CorpusInfo (name, version, fingerprint) + Skill (provenance, typed relations)
        |                                   |
  sie.chunking                        sie.graph.build ── typed Edges (+ overlays, provenance)
  Card chunk + body sections          sie.graph.paths ── learning paths, order_skills
        |                                   |
  BM25 (rank-bm25)   dense (ChromaDB, MiniLM ONNX)        |
        +-----------+-----------+                          |
              top-`pool` chunks each                       |
        RRF (k=60) -> optional cross-encoder (top `rerank_k` skills)
              |                                            |
        sie.router.route() -> RouteResult:                 |
          results + evidence, sie.confidence (route/clarify/abstain), timings
              |                                            |
        sie.compose (opt-in): intents -> skills -> prerequisites -> ordered plan
              |                                            |
        sie.engine.Engine (loads once, starts explicitly, status) ──+
              |
        sie.api (FastAPI, sie.schemas response models) · CLI · demo · sie.observability hooks

  eval/: datasets.toml -> run_eval (quality, confidence, OOS, multi-intent) -> benchmarks/
         perf (latency) · replay fixture + tests/test_regression.py (network-free)
```

**Guardrails.** Retrieval, graph, confidence, composition and every test run with no API key
and no model downloads: heavy libraries are imported inside functions, the test suite blocks
them and the network, and CI installs none of them. Results are deterministic (fixed seeds,
explicit tie-breaks, exact HNSW at this size); two eval runs produce byte-identical files.

## Layout

```
sie/            corpus, ingest, chunking, index/ (dense, sparse, fuse), rerank, hub, router,
                confidence, compose, graph/ (build, paths), engine, api, schemas, observability, llm
eval/           datasets.toml + 4 query sets, metrics, run_eval, replay, perf, collision,
                baseline/ (the corpus's keyword router, vendored verbatim), judge (optional LLM)
benchmarks/     RESULTS.md, metrics.json, per_query.jsonl, PERFORMANCE.md, charts, collision.json
docs/           PROPOSED_REQUIRES.md + proposed_requires.edges.json (opt-in overlay)
tests/          pytest (models mocked and blocked), fixtures/, integration/ (opt-in)
data/skills/    the vendored default corpus + its corpus.toml
```
