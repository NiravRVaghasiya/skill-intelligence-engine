# Skill Intelligence Engine

> A hybrid **semantic + graph-aware retrieval engine** over the
> [`ml-ai-skills`](https://github.com/NiravRVaghasiya/ml-ai-skills) library (38 `SKILL.md` files).
> It replaces the source repo's keyword router with a **RAG + GraphRAG** system that
> (a) retrieves the right skill for a free-text task and (b) generates a dependency-ordered
> **learning path** from the `requires` / `related` / `conflicts` graph.

**Top-1 routing accuracy goes from 43.2% to 95.5%** on 88 labeled queries (keyword router -> SIE: hybrid RRF (--no-rerank)), and from 34.8% to 82.6% on the 23 queries taken from the source repo's own eval cases. _Generated by `python -m eval.run_eval`._

SIE also fixes the vocabulary-collision failure the source repo documents.

## Why

The `ml-ai-skills` repo ships a deterministic keyword router and openly documents its weakness:
for *"Build a fraud detection model and evaluate it under severe class imbalance"* it returned
`computer-vision` first, because "detection" also appears in "object detection"
([docs/ROUTING.md](https://github.com/NiravRVaghasiya/ml-ai-skills/blob/main/docs/ROUTING.md)).
Every skill's frontmatter also encodes a dependency graph. The source only uses it to prepend
hard prerequisites to a route and to render and validate the graph. Nothing turns it into
ordered learning paths with see-also and conflict reasoning.

| Layer | What it does |
|-------|--------------|
| **Semantic router** | BM25 + dense (ChromaDB, all-MiniLM-L6-v2) over skill cards and body sections → RRF fusion → optional cross-encoder rerank → one hit per skill |
| **GraphRAG** | `requires` closure + deterministic topological sort → ordered learning path, `related` as see-also, `conflicts` flagged |
| **Eval harness** | top-1 / recall@3 / MRR / nDCG@3 with bootstrap CIs vs the source's keyword router (vendored byte-for-byte), plus ablations |
| **API** | FastAPI: `/search`, `/learning-path`, `/skill/{slug}`, `/health` |

On the 23 queries taken from the source repo's own `evals/` cases: keyword top-1 **0.348** / MRR 0.536 vs SIE top-1 **0.826** / MRR 0.895. CIs, paired deltas, tie sensitivity, ablations and every miss: [`benchmarks/RESULTS.md`](benchmarks/RESULTS.md). _Generated by `python -m eval.run_eval`._

**What the ablations say (computed):**

- **Main set, where the lexical gain comes from:** BM25 over the Card chunks alone (about the fields the keyword router reads) takes top-1 from 0.432 to 0.727 (better term weighting on the same text). Indexing the body sections too raises it to 0.920.
- **Source-authored set, where the lexical gain comes from:** BM25 over the Card chunks alone (about the fields the keyword router reads) takes top-1 from 0.348 to 0.696 (better term weighting on the same text). Indexing the body sections too lowers it to 0.652.
- **Main set:** the stronger single retriever is **BM25 only** (MRR 0.949 vs 0.927). SIE: hybrid RRF (--no-rerank) is +0.023 MRR against it and +0.399 against the keyword router.
- **Source-authored set:** the stronger single retriever is **dense only** (MRR 0.906 vs 0.749). SIE: hybrid RRF (--no-rerank) is -0.011 MRR against it and +0.359 against the keyword router.
- The keyword router is strongest on `-` queries (top-1 0.92; `-` marks the scaffold's original 12) and weakest on `symptom` queries (top-1 0.00).

**The collision case, reproduced**
(full input and output in [RESULTS.md](benchmarks/RESULTS.md#vocabulary-collision-case)):

| corpus | keyword router top-1 | SIE top-1 |
|---|---|---|
| ml-ai-skills@`c54f548` (the corpus on which the documented failure was observed) | `computer-vision` ✗ | `model-evaluation` ✓ |
| today's corpus (after the source's capability-tag audit) | `supervised-learning` ✓ | `model-evaluation` ✓ |

On both corpora SIE ranks both correct skills (`model-evaluation`, `supervised-learning`) in its
top-3. The keyword router ranks one of the two.

**Caveats (read before quoting the headline):**
- **Reranker:** while the cross-encoder row says *pending*, the headline system is hybrid RRF
  (`--no-rerank`). `huggingface.co` was unreachable from the network this was built on. See
  [Reranker weights](#reranker-weights).
- **Who wrote the queries:** the 76 new queries were written and audited by LLM agents that saw
  only the skill catalog, and the set was frozen before either system ran. The source-authored
  set exists precisely because I didn't write it.
- **Ties:** both systems break exact score ties alphabetically. RESULTS.md reports how much of
  each system's top-1 that decides.

## Demo

```text
$ python -m sie.router "impute missing values and encode categoricals" --no-rerank -k 3
[router] mode=hybrid ranking=rrf
 1. data-preprocessing           score=0.033  [Card]
 2. feature-engineering          score=0.032  [Workflow]
 3. ml-problem-framing           score=0.030  [Workflow]

$ python -m sie.router --path rag-evaluation
[path] learning path to rag-evaluation (2 steps, hard `requires` edges only)
  1. rag-pipeline               [workflow/llm, intermediate]
  2. rag-evaluation             [workflow/llm, intermediate]  <- target
  see also:  llm-evaluation, model-evaluation, ai-ml-security
  conflicts: none
```

The corpus declares only 2 `requires` edges, so most paths are one node today.
[docs/PROPOSED_REQUIRES.md](docs/PROPOSED_REQUIRES.md) proposes 9 evidence-backed edges for the
upstream maintainer (for example `pytorch-patterns → training-deep-models`). They were verified
adversarially and are deliberately *not* applied here.

## Quickstart (clone-and-run, LLM optional)

```bash
git clone <this-repo> && cd skill-intelligence-engine
python -m venv .venv && . .venv/Scripts/activate     # Windows (Git Bash); `source .venv/bin/activate` elsewhere
pip install -r requirements.txt

python -m sie.ingest --skills data/skills --expect 38   # load report: 38 skills, 0 skipped
python -m sie.router --build                            # dense index -> data/chroma/ (~30 s on CPU)
python -m sie.router "impute missing values and encode categoricals"
python -m sie.router --path rag-evaluation              # learning path (no index needed)

python -m eval.run_eval                                 # benchmarks -> benchmarks/RESULTS.md + chart
python -m eval.collision --source ../ml-ai-skills       # collision case (needs the source git history)

uvicorn sie.api:api --reload
#   GET /search?q=...&k=5          hybrid retrieval ("reranked": whether the cross-encoder ranked this response)
#   GET /learning-path?target=rag-evaluation
#   GET /skill/{slug}              metadata + requires / required_by
#   GET /health
```

Ablations: `--no-rerank` (RRF only), `--mode dense|sparse` (one retriever), `--pool N`
(candidate chunks per retriever).

### Reranker weights

The cross-encoder (`cross-encoder/ms-marco-MiniLM-L-6-v2`) loads from the first of these that
is set or present: `$SIE_RERANKER` (a Hugging Face id or a local directory), then
`data/models/ms-marco-MiniLM-L-6-v2/`, then the Hugging Face hub id. This is precedence, not a
fallback chain. If the chosen source can't load, the router says so once and falls back to RRF
order; it never hangs retrying. After you copy the weights in,
`python -m eval.run_eval --no-build` fills in the pending row. The dense embedder
uses chromadb's ONNX export of all-MiniLM-L6-v2, which downloads from chroma's S3 bucket
rather than the Hugging Face hub. Set `SIE_EMBEDDER=sentence-transformers` for the PyTorch
path.

## Architecture

```
            data/skills/*/SKILL.md  (38 skills; frontmatter + ## sections)
                         |
                  sie.ingest  -> load report (skips / duplicates / dangling refs, never silent)
                         |
        +----------------+-------------------------------+
        |                                                |
  sie.chunking                                     sie.graph.build
  1 "Card" chunk per skill (name + description,    NetworkX DiGraph
  minus its "NOT for ..." clause, + capabilities)  requires: prereq -> skill
  + body sections (code fences intact)             related / conflicts kept per node
        |                                                |
  +-----+------------------+                       sie.graph.paths
  |                        |                       closure + lexicographic topo sort
BM25 (rank-bm25)   dense: ChromaDB (cosine)         -> path, see-also, conflicts
  |                 all-MiniLM-L6-v2 (ONNX)              |
  +----------+-------------+                             |
             | top-20 chunks each                        |
     RRF (k=60, one entry per skill per list)            |
             |                                           |
     cross-encoder rerank (optional, MaxP per skill)     |
             |                                           |
     dedup -> one Hit per skill                          |
             |                                           |
             +----------------> FastAPI  <---------------+
                           /search  /learning-path  /skill/{slug}  /health

eval/: keyword baseline (vendored) vs SIE ablations -> metrics + bootstrap CIs -> benchmarks/
```

**Guardrails.** The core never needs an LLM (`sie/llm.py` defaults to `noop`; the LLM is only
used for the optional judge). Heavy libraries are imported lazily. The test suite blocks
chromadb, sentence-transformers, torch, onnxruntime and the network, so CI never downloads a
model. Retrieval is deterministic: fixed seeds, explicit tie-breaks, and exact HNSW at this
corpus size. Two eval runs produce byte-identical per-query output.

## Layout

```
sie/            ingest, chunking, index/ (dense, sparse, fuse), rerank, hub, router, graph/, llm, api
eval/           queries.jsonl (88), queries_source_evals.jsonl (23), metrics, run_eval, collision,
                baseline/ (source keyword router, vendored verbatim + provenance), judge (optional LLM)
benchmarks/     RESULTS.md, results.png (+ dark), per_query.jsonl, collision.json
docs/           PROPOSED_REQUIRES.md: missing prerequisite edges proposed upstream
tests/          pytest; heavy models mocked and blocked
data/skills/    vendored ml-ai-skills corpus (38 canonical skills @ 8328c60)
```
