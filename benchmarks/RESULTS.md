# Benchmarks — SIE vs the keyword baseline

Everything between `BEGIN`/`END` markers is generated:

```bash
python -m eval.run_eval                          # metrics, metrics.json, results.png, per_query.jsonl
python -m eval.run_eval --smoke                  # no models: re-derive and diff against metrics.json (CI)
python -m eval.collision --source ../ml-ai-skills  # collision case (needs the source git history)
```

Latency is deliberately not in this file (it is machine-dependent): see [PERFORMANCE.md](PERFORMANCE.md).

## Method

**Systems.** The baseline is the source repo's `scripts/router.py`, vendored byte-for-byte
(`eval/baseline/SOURCE.md`, hash-checked by the tests). It is scored generously: as a *full
ranking* of all 38 skills using its own `score_skill()` and tie-break, with no min-score cut
and no prerequisite expansion. `route()` exactly as shipped (top-5, min-score 1, prerequisites
prepended) is reported as a second row. SIE rows ablate the pipeline: BM25 only, dense only,
hybrid RRF (`--no-rerank`), and hybrid + cross-encoder. SIE rows are scored through
`HybridRouter.route()`, so each query also gets the router's routing confidence
(`sie/confidence.py`); the keyword systems have none.

**Query sets.**
- *Main* (`eval/queries.jsonl`, 88 queries, all 8 domains, every skill covered): the scaffold's
  original 12 queries, plus 76 new ones (2 per skill). Those 76 were written by four LLM
  (Claude) writer agents, each given only the skill catalog and told not to run any code,
  retriever or search. Four separate auditor agents then challenged every gold label and
  checked for copied phrasing and fairness to both systems; they rewrote 11 queries and gave
  one query two acceptable skills. The file was frozen (sha256 recorded in Provenance)
  before either system had been run on it. None of the 76 shares a 4-word run with its gold
  skill's description.
- *Source-authored* (`eval/queries_source_evals.jsonl`, 23 queries): the `input` of every
  `evals/*.yaml` behavioral case in ml-ai-skills, with that repo's own skill labels used
  verbatim (`python -m eval.build_source_queries`). Neither system nor its author wrote them.
  Some cases deliberately straddle two skills (e.g. RAG prompt injection vs `ai-ml-security`).
- *Out-of-scope* (`eval/queries_out_of_scope.jsonl`, 30 queries, gold `null`): 10 unrelated,
  10 adjacent-domain (software/data work no skill covers), 10 near-miss (ML-flavored but no fitting
  skill). One LLM writer agent with only the catalog, one adversarial auditor agent that replaced
  every query a human router might plausibly send to some skill (2 of 30). Frozen before scoring.
- *Multi-intent* (`eval/queries_multi_intent.jsonl`, 25 requests): 20 with 2–4 intents mapping
  to distinct skills, plus 5 single-intent controls that contain conjunctions. Gold is one list
  of acceptable skills per intent. Same writer/auditor protocol; the writer knew nothing about
  how `compose()` splits. Frozen before scoring.
- Every set's origin is declared in `eval/datasets.toml` (`scaffold`, `synthetic-llm`,
  `source-authored`; none is `human-collected`).

**Metrics.** Each query is scored by the rank of its first acceptable gold skill in the top
10: top-1 (= recall@1), recall@3, recall@5, MRR, nDCG@3, nDCG@5. `[lo, hi]` is a 10,000-resample
percentile bootstrap 95% CI (seed 42). The delta table is paired over the same queries.
Confidence: top-1 accuracy per level, the share routed without a question and its accuracy, and
clarify/abstain shares; on the out-of-scope set, the share of each action (abstain is correct,
clarify is acceptable, route is wrong). Multi-intent: per request, intent recall (gold intents
covered by a returned skill), precision (returned skills that match some gold intent), exact
match and count match, averaged over requests; pooled coverage is reported next to it.

**Design choices fixed before any evaluation run, none tuned on these queries:**
- One "Card" chunk per skill (display name + description + capability tags) with the
  description's trailing "NOT for X (see other-skill)" clause dropped. That clause names
  *other* skills' topics.
- A `"<skill> - <section>"` header line on every body chunk.
- all-MiniLM-L6-v2 embeddings; BM25 on lowercase alphanumeric tokens with no stopwords or
  stemming.
- Candidate pool of 20 chunks per retriever, collapsed to the best chunk per skill.
- RRF with k=60.
- Cross-encoder `ms-marco-MiniLM-L-6-v2` over all candidate chunks of the top-20 fused skills,
  with the max chunk score per skill.
- Confidence thresholds (`min_similarity` 0.30, `min_coverage` 0.40, `min_margin` 0.03) and the
  hybrid/dense rules; `compose()`'s splitting rules as first written. Post-hoc changes to the
  BM25-only confidence rule and to `compose()` are listed, with their first-measurement numbers,
  in the generated confidence and multi-intent sections below.

### Observations (computed)

- **Main set, where the lexical gain comes from:** BM25 over the Card chunks alone (about the fields the keyword router reads) takes top-1 from 0.432 to 0.727 (better term weighting on the same text). Indexing the body sections too raises it to 0.920.
- **Source-authored set, where the lexical gain comes from:** BM25 over the Card chunks alone (about the fields the keyword router reads) takes top-1 from 0.348 to 0.696 (better term weighting on the same text). Indexing the body sections too lowers it to 0.652.
- **Main set:** the stronger single retriever is **BM25 only** (MRR 0.949 vs 0.927). SIE: hybrid RRF (--no-rerank) is +0.023 MRR against it and +0.399 against the keyword router.
- **Source-authored set:** the stronger single retriever is **dense only** (MRR 0.906 vs 0.749). SIE: hybrid RRF (--no-rerank) is -0.011 MRR against it and +0.359 against the keyword router.
- The keyword router is strongest on `-` queries (top-1 0.92; `-` marks the scaffold's original 12) and weakest on `symptom` queries (top-1 0.00).

### Confidence vs correctness (heuristic levels, uncalibrated)

Every SIE router grades its top result `high` (action: route), `medium` or `low` (clarify) or `none` (abstain) with the rules in `sie/confidence.py`. Its thresholds and its hybrid and dense rules were fixed before any of these sets were scored and are not tuned on them; the BM25-only rule was changed after the first measurement (see *Changed after the first measurement* at the end of this section). The levels are not probabilities. A level cell is the top-1 accuracy of the queries at that level <sub>n = how many</sub>. *routed* is the share with action `route` (answered without a question); *top-1 when routed* is the accuracy a caller that acts only on `route` gets. Every query here has a correct skill, so each abstention is a false abstain. Keyword systems and the Card-only ablation have no confidence and are omitted.

**Changed after the first measurement.** Two components were changed after the first full run had scored them on the default query sets (`eval/datasets.toml`), knowing how the earlier code did there. Their current numbers on those sets are therefore **not held-out measurements**. The figures quoted here are that first measurement, of the earlier code (constants in `eval/run_eval.py`; that code no longer runs).

- *BM25-only confidence rule* (`sie/confidence.py`): weak lexical coverage used to make a BM25-only router abstain (`none`); it now answers `low` (clarify). First measurement, earlier code: BM25-only abstained on 55.9% of the in-scope queries (62 of 111, main + source). Its clarify/abstain split, in scope and out of scope, is post hoc.
- *`compose()` intent splitting* (`sie/compose.py`): a single-intent request is routed verbatim; an intent whose pronoun was resolved to the first intent's object is routed as written instead when the resolved text selects a skill an earlier intent already has and the written text selects a new one, and a long substituted object phrase is capped; noun homographs of action verbs (test, log, train, index, ...) start an intent only before a verb-object word; "et al." never ends a sentence and "etc." ends one unless a lowercase word follows. First measurement, earlier code (SIE: hybrid RRF, mean over requests): intent recall 0.593, precision 0.803, exact 0.280, count match 0.480. Its multi-intent numbers are post hoc.

### Multi-intent composition (n=25) — `eval/queries_multi_intent.jsonl`

Each request asks for one or more things; gold is one list of acceptable skills per intent. SIE: hybrid RRF (--no-rerank) is scored three ways. (b) uses the number of gold intents, which no real caller knows: it is an upper reference for plain routing, not a system. (c) is `sie.compose.compose()` with its defaults (k=3, max_intents=5): conservative splitting, one routed skill per intent, intents that abstain select nothing; the prerequisites it adds from the graph are not counted. *Intent recall* = share of a request's gold intents covered by a returned skill, averaged over requests (every request weighs the same); *pooled coverage* = covered gold intents / all 63 gold intents of the set; *precision* = share of returned skills that fit some intent; *exact* = both 1; *count match* = as many distinct skills as gold intents.

`compose()` was changed after its first measurement on the default multi-intent set (see *Changed after the first measurement* at the end of the confidence section; first measurement, earlier code: intent recall 0.593, precision 0.803, exact 0.280, count match 0.480), so (c) there is not a held-out measurement.
